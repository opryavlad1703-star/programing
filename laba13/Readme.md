### 1. Що таке розширення PDO у PHP та які суттєві переваги воно надає у порівнянні з застарілим `mysql_*` та процедурним стилем `mysqli`?
* **PDO (PHP Data Objects)** — це об'єктно-орієнтований шар абстракції бази даних для PHP, який надає єдиний уніфікований інтерфейс для роботи з різними СУБД.
* **Основні переваги:**
  * **Універсальність (абстракція СУБД):** PDO підтримує понад 12 різних систем баз даних (MySQL, PostgreSQL, SQLite, MS SQL тощо). Зміна бази даних потребує лише зміни рядка підключення DSN без переписування усіх SQL-запитів.
  * **Об'єктно-орієнтований стиль та винятки:** Надає зручну обробку помилок через `PDOException` і гнучке мапування результатів (у масиви, об'єкти, класи).
  * **Безпека за замовчуванням:** Вбудована та повноцінна підтримка підготовлених виразів (Prepared Statements), яка повністю була відсутня в застарілому модулі `mysql_*` (вилученому з PHP 7.0).

### 2. Яким чином підготовлені вирази (Prepared Statements) гарантують захист від SQL-ін’єкцій, і чому конкатенація змінних безпосередньо в SQL-рядок вважається критичною вразливістю?
* **Принцип захисту:** Підготовлені вирази розділяють виконання SQL-запиту на два незалежних етапи:
  1. **Етап компіляції (Prepare):** Шаблон запиту із плейсхолдерами (наприклад, `:user_id` або `?`) відправляється на сервер бази даних, де аналізується та компілюється його структура та логіка.
  2. **Етап виконання (Execute):** Дані від користувача передаються окремо. СУБД сприймає їх виключно як літеральні значення (рядки або числа), незалежно від наявності в них лапок чи спецсимволів. Дані ніколи не стають частиною виклику SQL-команд.
* **Вразливість конкатенації:** Звичайне склеювання рядків (`"WHERE user_id = " . $userInput`) дозволяє зловмиснику передати керуючі символи SQL (наприклад, `' OR '1'='1`), що змінює логіку самого запиту, дозволяючи обійти авторизацію чи видалити дані.

### 3. Чому для параметрів `LIMIT` та `OFFSET` у методі `TaskRepository::findAllByUser()` використовується метод `bindValue()` з типом `PDO::PARAM_INT`, а не передача масиву значень у `execute()`?
* Коли параметри передаються масивом безпосередньо в метод `$stmt->execute([':limit' => $limit])`, PDO за замовчуванням приводить всі значення до рядкового типу (`PDO::PARAM_STR`).
* Якщо вимкнено емуляцію підготовлених виразів (`PDO::ATTR_EMULATE_PREPARES => false`), MySQL/MariaDB очікує в конструкціях `LIMIT` та `OFFSET` суворо цілочисельні значення (integers). Передача `LIMIT '5'` у вигляді рядка викликає синтаксичну помилку SQL.
* Метод `bindValue(':limit', $limit, PDO::PARAM_INT)` явно вказує драйверу PDO передати параметр як числовий тип `INT`.

### 4. Для чого призначений метод `PDO::lastInsertId()`, у який момент його необхідно викликати і що він повертає?
* **Призначення:** Отримання ідентифікатора (`id`), який був автогенератором (`AUTO_INCREMENT`) призначений останньому доданому рядку в базі даних.
* **Момент виклику:** Його необхідно викликати **одразу після** успішного виконання операції створення запису (`INSERT`) на об'єкті `$pdo`, до виконання наступних запитів.
* **Що повертає:** Рядок (або числове значення у вигляді рядка), що відповідає первинному ключу останньої вставленої сутності.

### 5. Як саме реалізується постранична пагінація в реляційних базах даних? Поясніть формулу розрахунку зміщення: `offset = (page - 1) * perPage`.
* **Реалізація:** У реляційних БД пагінація реалізується комбінацією двох операторів SQL:
  * `LIMIT` — визначає максимальну кількість записів, яку потрібно повернути на одній сторінці (`perPage`).
  * `OFFSET` — вказує, скільки записів від початку результату потрібно пропустити (`offset`).
* **Пояснення формули `offset = (page - 1) * perPage`:**
  * На **1-й сторінці** (`page = 1`): `(1 - 1) * 5 = 0` $\rightarrow$ пропустити `0` записів (`OFFSET 0`), показати перші 5 записів.
  * На **2-й сторінці** (`page = 2`): `(2 - 1) * 5 = 5` $\rightarrow$ пропустити перші `5` записів (`OFFSET 5`), показати наступні 5 записів (з 6 по 10).
  * На **3-й сторінці** (`page = 3`): `(3 - 1) * 5 = 10` $\rightarrow$ пропустити `10` записів (`OFFSET 10`), показати записи з 11 по 15.
